# Rust SDK 性能设计

## 1. 性能模型

性能设计在不改变协议、安全性和公开 API 语义的前提下，控制以下成本：

| 维度 | 指标 |
|---|---|
| 请求延迟 | SDK 本地准备/解析耗时，整体 p50/p95/p99，冷连接与热连接分别测量 |
| 并发吞吐 | 完成请求数、在途数、等待时间、错误率 |
| CPU | 编码、签名、响应解码和 SSE 解析的 CPU 时间 |
| 内存 | 单次分配次数/字节、并发峰值内存、流式缓冲上限 |
| 构建 | 冷构建/增量构建时间、rlib 大小、最小消费程序大小 |

网络往返和服务端执行时间通常是云 API 延迟的重要组成部分，但不能据此忽略 SDK 的 CPU 和内存。先用离线执行基准隔离 SDK 本身，再用本地 HTTP 服务验证连接、并发与流式行为。没有实现和测量前不承诺固定 QPS、延迟或分配次数。

## 2. 热路径与职责分离

```text
借用强类型请求
  → 直接编码为 Vec<u8>
  → 转移所有权为可共享 Bytes
  → 凭证缓存读取 Arc<Credentials> 快照
  → 对 body 字节求摘要，构建签名
  → 共享的非泛型异步执行主体
  → 受限读取响应字节
  → 解析协议外层并直接解码业务类型
  → 返回拥有数据所有权的 ApiResponse<T>
```

- 产品 Client 只保存共享 core Client 和静态产品信息，不保存每请求的状态。
- 请求方法接收 `&Request`；执行期间借用请求，不要求为了调用而深拷贝全部字段。
- service、version、Action 等来自生成的静态描述，不在每次调用时构造产品注册表或查找反射信息。
- JSON 模型是结构体，不先变成通用 HashMap、serde_json::Value 或字符串再二次转换。
- 泛型仅承担类型相关的编码/解码；凭证、网络、重试状态机保持共享实现，减少接口数量增大带来的单态化膨胀。
- 不默认对大体积错误、整个 Client 内部状态或业务响应派生无必要的 trait。

facade 只做编译期 re-export，没有运行时代理、路由查表或额外 Client 包装层。

## 3. 请求编码与字节所有权

### 3.1 常规 JSON

使用 serde_json::to_vec 或等价的直接 writer 编码路径，避免 `Request → Value → String → Vec<u8>`。

同一份已编码 body 同时用于摘要与发送，防止二次编码造成时间开销和签名差异。传输前转为 Bytes，重试只复制引用，不复制完整 body。每次重试仍重新获取时间、有效凭证并计算 Authorization。

对同一逻辑请求且字节未改变的 body，payload SHA256 可以在首次尝试前计算一次并复用；不能把包含时间、凭证或目标的完整签名一并复用。multipart 的 boundary 和编码结果也固定于该次逻辑调用，不在重试时重新生成。

请求有额外字段时使用专门的序列化包装器合并，普通请求不为此分配 Map。扩展路径校验字段名冲突，不能通过转成 Value 来简化所有请求的实现。

已知大小的缓冲使用合理容量；不为测量长度把整个请求先编码一遍。初始容量不根据未经限制的用户输入分配，避免过度预留。全局可变缓冲池、线程本地大缓冲和 SmallVec 等优化不作为基础设计要求。

### 3.2 二进制与 multipart

支持接收调用方已有的 Bytes，避免强制复制为 Vec。小型 multipart 可编码为可重放字节体，必须有请求体限制。

大文件不能默认全量复制到内存。文件上传能力采用显式、可说明重放语义的 body 类型：可重新打开的文件源可按需重放，一次性流不可自动重试。TC3 需要完整 payload hash 时，对可重放源先计算摘要再发送，不能一边发送后才补签名；预读与再次读取之间必须保证内容一致。

未提供这种源能力时，返回不支持/超限错误，不能以“不受限缓冲到内存”冒充流式上传。

## 4. 响应解析

### 4.1 避免完整 JSON 树和重复业务解码

不采用先将完整响应反序列化为错误模型、再反序列化为成功模型的默认实现，也不要求先构建 Value DOM。

协议层可将 `Response` 借用为 serde_json::value::RawValue（开启 raw_value），提取少量公共字段和错误信息，再从原始片段直接解码目标业务结构。错误路径不创建成功模型；成功路径不构造完整的错误/未知字段树。

RawValue 会进行语法扫描，随后业务解码仍需要读取业务片段，不能称为“全响应仅扫描一次”或完全零拷贝。其优势是避免 DOM 和重复结构化分配；应与自定义 envelope visitor 实现做实测比较，再选择复杂度适当的实现。

RequestId 从协议层归一化到 metadata；不为了剥离一个字段而重建全部 JSON 对象。普通公开响应拥有 String、Vec 等数据，避免把底层响应缓冲的生命周期传播到所有用户 API。需要原始 JSON 的通用调用提供独立入口，不强制强类型响应同时保留一份原始 body。

### 4.2 大响应保护

Content-Length 只作提前拒绝参考，实际按累计读取字节数实施上限，不能信任缺失或错误的长度。超过上限及时停止读取并返回错误；如果允许解压缩，上限作用于解压后的数据，避免压缩膨胀。

正常完成时消费并释放响应体，有利于连接复用；超限、取消或无效响应时及时释放资源，不为了保住一条连接继续读取任意大小的数据。

默认不把原始 body 复制到日志或错误。确需诊断时使用显式、有长度上限的安全接口，并说明敏感数据风险。

## 5. Client、连接和调度

### 5.1 资源共享

Client 采用轻量 Clone，共享 Arc<ClientInner>。产品 Client 持有 core Client 的轻量克隆，而不是新建 HTTP Client。

ClientInner 保存不可变配置、共享 Transport、凭证提供器和少量并发控制状态。已构建的 Client 不允许通过 setter 修改 Region、endpoint 或 TLS 配置；单次差异使用 RequestOptions，避免加锁读取一份不断变化的全局配置。

HTTP 连接池在 client 生命周期内复用，代理、TLS 和池配置在构建时完成。HTTP/2 按服务端协商使用，不强制所有端点支持，也不把 HTTP/2 自动等同于更高性能。

用户传入既有 transport 时复用其连接资源。不同代理或 TLS 身份要求不同连接配置，不能为了共享而混用安全上下文。CVM 元数据使用隔离的专用 transport。

### 5.2 并发与背压

SDK 不为每个请求创建线程或 detached Tokio task；请求 future 由调用方执行器轮询。异步等待不使用 thread::sleep。

提供可选 max_in_flight，在共享 Client 层控制实际在途尝试。默认不擅自设置一个与服务配额无关的并发值，但明确说明大量并发由调用方负责限界。

- 等待许可包含在 deadline 内，支持取消。
- 重试退避期间释放在途许可，避免失败请求占满全部发送容量。
- HTTP body 读取期间持有许可；SSE 的许可持续到流结束或被丢弃，而不是收到响应头就释放。
- SSE 长连接与普通请求建议使用独立 Client/并发预算，避免长流耗尽普通请求容量。
- 只有许可不能限制调用方无限创建等待任务；队列长度和总并发仍需应用侧控制，SDK 不维护隐藏的无界请求队列。

传输层动态分派和 boxed future 有成本，但只出现在可替换 I/O 边界。暂不增加泛型 Client、静态/动态双 API 或多级 middleware 框架；若无网络微基准显示此处成为显著瓶颈，再比较设计。

## 6. 凭证与签名

### 6.1 凭证缓存

缓存返回 Arc<Credentials>，不为每次签名复制 SecretId、SecretKey、Token 字符串。快路径短暂读取缓存及到期时间，不访问磁盘、环境配置文件或 STS。

静态/环境/配置凭证在提供器初始化或首次解析时装载；主动重载必须是显式行为。OIDC 文件在刷新路径读取，文件读取不阻塞异步执行线程。

缓存值读取可先用标准库短临界区 RwLock 实现，读取后立刻释放锁，不能跨 await。真正的并发刷新由异步协调机制实现，最多一项刷新进行网络访问。允许仍有效的旧快照继续服务时，不让普通读取等待整个刷新网络往返；无法安全使用旧快照时其他调用才等待刷新。

刷新失败与取消必须清理刷新状态并唤醒等待者；采用短暂失败退避，避免每个请求都触发一次 STS 失败。不得永久缓存失败或返回已过期凭证。

不声称快路径无锁。只有测量确认短锁竞争显著时才评估原子快照库，不为名义上的无锁提前引入依赖和复杂回收机制。

### 6.2 签名分配

SHA256/HMAC 使用成熟密码库。固定长度摘要在栈上表示，十六进制和签名字符串使用已知容量，避免多轮临时 String 拼接和不必要编码转换。

公共 Header 使用结构化 HeaderMap，不先建字符串 Map 再整体转换。静态 Header 名复用常量，动态 Header 值仍按协议校验，不能跳过校验来换性能。

默认不缓存派生签名密钥。若基准显示多次 HMAC 派生有显著成本，可评估按凭证代次、UTC 日期和 service 建立有界缓存；要求凭证刷新和跨日立即失效、严格限制缓存容量及密钥存活时间，并衡量锁竞争。禁止把原始 SecretKey 拼成缓存 key 或输出到 Debug。

## 7. SSE 与分页内存

SSE 解码按字节增量处理，正确处理 UTF-8 和 CRLF 跨分块边界。不对每块重复扫描并复制整个累积字符串，不在每读一行时重新分配全部事件内容。

- 仅缓冲当前未完成事件及必要尾部字节，按事件配置大小上限。
- 不在内部用无界 channel 预读事件；消费者 poll 驱动读取。
- 底层网络栈可能有有限预读，不声称完全没有缓冲。
- 原始事件可使用 Bytes 切片，但必须避免小片段长期引用过大的底层内存块；必要时对小尾部做受控复制。
- 产品 JSON 事件的解码成本按消费速度发生，不先攒完整流。
- 丢弃流立即释放本地响应资源；不能承诺这会撤销服务端已经开始的业务操作。

分页默认按需取一页，内存随当前页大小变化，不自动收集所有结果。默认不预取下一页，避免慢消费者、限流或取消时发起多余请求。若提供预取选项，必须有显式且有限的预取窗口。

## 8. 大 JSON 与执行器公平性

不能仅因为 API 是 async 就认为序列化和 JSON 解码不会占用执行器。大响应解析是同步 CPU 工作。

正常小响应直接解码，避免每次 spawn_blocking 带来的任务切换和数据转移开销。先测量不同大小和嵌套结构下的 CPU 时间；只有大响应确实影响并发尾延迟时，才提供阈值可调的有界阻塞解析路径或原始字节接口。

阻塞解析启动后通常不能强制中断，必须限制并发数和输入体积，并明确 timeout 结束等待不等于解析立刻停止。不能无限 spawn_blocking，也不默认引入专用线程池或 rayon。

## 9. 构建与代码体积

产品 optional dependency 是构建隔离边界，未启用产品不参与消费项目构建。开启一个产品不等于仅编译调用到的方法，模型派生和类型检查仍有成本。

- 只生成需要的 serde 方向与 trait，实现确有用途的 Serialize/Deserialize，不对所有结构体无条件派生双向转换、Clone、Debug、Default。
- 请求和响应确实共用的嵌套模型可实现双向转换；生成器依据引用关系决定，不通过产品 feature 改变同一公共类型的布局。
- 不滥用 #[inline(always)]，不把大型执行函数强制内联进每个产品方法。
- 请求构造器使用普通 builder，不为几十个可选字段生成指数级 typestate 组合。
- 生成器不属于 SDK 正常依赖；构建时不联网、不重新生成产品源码。
- LTO、strip、codegen-units 和 panic 策略由最终应用决定，基准中固定，不在 lib 中强制设置。

## 10. 离线基准设计

```text
crates/core/benches/
├── encode.rs          # 请求编码与扩展字段
├── signing.rs         # TC3、小/大 body、摘要复用
├── decode.rs          # 强类型成功/错误、RawValue/visitor 对照
├── credentials.rs     # 缓存读取、并发刷新
├── execute.rs         # MockTransport 的完整本地调用成本
└── sse.rs             # 不同分块、事件大小和慢消费者

tools/perf/            # 不发布、不进入运行时依赖
├── consumer-minimal/  # 无产品
├── consumer-cvm/      # 仅 CVM
└── consumer-multi/    # 多产品
```

基准依赖只作为 dev-dependency 或独立工具依赖。统计工具可使用 Criterion，不进入 SDK 运行时依赖图。

覆盖场景：

| 维度 | 样例 |
|---|---|
| 请求/响应体积 | 1 KiB、64 KiB、1 MiB，以及超限样例 |
| 数据结构 | 浅层、深层、多数组、可选字段多、未知字段多 |
| 并发 | 1、16、64、256；同时记录线程与连接配置 |
| 凭证 | 缓存命中、同时到期、刷新失败、刷新 future 取消 |
| 网络 | Mock 零网络、本地 HTTP、冷/热连接、慢响应、断流 |
| SSE | 多事件一块、逐字节分块、大事件、慢消费者、取消 |

报告至少包含环境、工具链、提交、feature、release profile、样本分布、误差和输入规模。延迟分解为排队、凭证、编码、签名、发送等待和解码；并发测试同时报告错误率和资源峰值，不只报告成功 QPS。

分配测量和 CPU 延迟测量分开执行，避免分配探针本身扭曲延迟。连接复用用本地服务记录连接数验证；凭证并发测试核对实际刷新次数；SSE 背压测试核对慢消费时峰值内存是否有界。

实现建立基线后，用同环境的相对回归阈值审查变化，不凭单次测量或跨机器绝对值决定性能优劣。正确性测试始终优先；固定性能目标必须有对应输入和资源约束。

## 11. 不采用的默认优化

不为了性能默认引入 unsafe、手写 SIMD、全局内存池、复杂无锁缓存、全泛型传输栈、无限请求并发或推测性分页预取。不能用取消 TLS 校验、忽略响应错误、无限缓存、擅自重试副作用操作来换吞吐。

优化优先顺序是：消除重复工作和无界资源使用 → 测量热点 → 选择局部优化 → 用正确性测试和相同基准验证。当前文档规定结构和验证方法，不表示任何性能数据已经得到实测。
